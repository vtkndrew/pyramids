# Пирамидки

Локальная головоломка на React, TypeScript и Vite. Перенесите пирамидку с первого стержня на последний: можно брать только верхний диск и класть его на пустой стержень либо на больший диск.

Адрес игры после публикации: **https://vtkndrew.github.io/pyramids/**.

## Запуск

Нужен Node.js 22.12+ (либо Node.js 20.19+) и npm.

```sh
npm install
npm run dev
```

Откройте адрес из терминала (обычно http://127.0.0.1:5173). Для остановки сервера нажмите Ctrl+C. После установки зависимостей игра работает локально без доступа к интернету, внешних шрифтов и сервисов.

## Управление

- Перед началом выберите 3–6 стержней и 3–10 дисков. По умолчанию: 3 стержня и 5 дисков.
- Выберите режим: «Обычный» (по умолчанию) разрешает переносы на любой подходящий стержень; «Хардкор» — только на соседний слева или справа. Первый и последний стержни не являются соседями. Правило размеров дисков действует в обоих режимах. Режим применяется только при начале новой игры и сохраняется при перезапуске.
- После «Начать игру» открывается окно выбора управления с демонстрацией. В обычном режиме по умолчанию выбрано «Перетаскивание», в хардкоре — «Свайпы». Партия и таймер запускаются только после «Играть». Закрытие окна возвращает к настройкам без сброса существующей партии.
- Нажмите на исходный стержень, затем на стержень назначения. Повторный клик по исходному снимает выбор. Допустимые назначения подсвечиваются.
- «Перетаскивание»: потяните из любой части ячейки непустого стержня и отпустите над нужной ячейкой. Переносится только верхний диск. Отпускание вне поля или над исходным стержнем отменяет перенос.
- «Свайпы» доступны только в хардкоре: смахните по ячейке влево или вправо — верхний диск переместится на один соседний стержень. Длина свайпа не увеличивает расстояние. Нажатия продолжают работать и при включённых жестах.
- Клавиатура: цифра 1–6 выбирает исходный стержень, следующая — целевой. Escape снимает выбор или отменяет жест. Tab / Shift+Tab перемещают фокус, Enter или пробел активируют кнопки; стрелки меняют настройки. Игровые клавиши не действуют в формах, модалках и на паузе.
- Кнопка «Управление» (на телефоне — в «Меню») открывает выбор способа во время партии. Поле скрывается и время останавливается; «Применить» меняет управление без сброса позиции, истории и времени. Закрытие без применения сохраняет прежний способ. Ручная пауза остаётся включённой, если была включена до открытия окна.
- «Отменить» и «Повторить» позволяют пройти всю историю. Новый допустимый ход после отмены удаляет будущую ветку. Ошибка или выбор диска историю не меняют.
- «Начать заново» сразу сбрасывает текущую партию, сохраняя настройки и способ управления, без повторного окна выбора.
- «Настройки» (на телефоне — в «Меню») открывает форму. «Начать игру» открывает выбор управления, а «Играть» применяет выбранные значения и создаёт новую партию. «Назад к игре» сохраняет текущую партию и историю.
- После победы можно отменить ход и продолжить игру или повторить ход для возврата к победе.
- «Пауза» останавливает таймер и полностью скрывает поле. На паузе нельзя делать, отменять и повторять ходы, но доступны настройки и перезапуск. «Продолжить» возвращает ту же позицию и продолжает отсчёт; выделение диска сбрасывается. Возврат из настроек сохраняет ручную паузу. Новая игра или перезапуск снимают паузу и сбрасывают время. После победы кнопка паузы недоступна.
- Таймер запускается с началом партии. В настройках и после победы время стоит на паузе; при возврате к игре или отмене победного хода отсчёт продолжается. Отмена и повтор не отматывают время. Новая игра и «Начать заново» сбрасывают таймер. При переключении вкладки, сворачивании приложения или блокировке экрана включается автопауза. После возвращения нажмите «Продолжить».

Партия и способ управления автоматически сохраняются на устройстве: после обновления страницы можно продолжить последнюю игру. Все стержни и диски адаптируются к ширине поля без горизонтальной прокрутки. В режимах жестов на поле отключено выделение текста; в настольной компоновке с перетаскиванием прокручивать страницу можно за пределами поля.

## Установка приложения и работа без интернета

Откройте **https://vtkndrew.github.io/pyramids/** на телефоне. В первоначальных настройках и мобильном меню есть «Установить приложение». На компьютере эта кнопка также есть в настройках и панели партии. Она открывает раздел «Приложение»; автоматических предложений установки нет.

**Android:** в разделе «Приложение» нажмите «Установить» и подтвердите системный запрос. Если кнопка недоступна, откройте меню браузера и выберите «Установить приложение» или «Добавить на главный экран» (название зависит от браузера). При отмене можно вернуться к установке позже через меню браузера.

**iPhone / iPad:** откройте сайт в Safari → «Поделиться» → «На экран “Домой”» → «Добавить». Если есть переключатель «Открывать как веб-приложение», оставьте его включённым. Игра появится на главном экране и будет открываться в отдельном окне. [Инструкция Apple](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios).

Первый запуск требует интернета. Перед отключением сети дождитесь сообщения **«Готово к работе без интернета»** в разделе «Приложение». В установленном приложении проверьте его ещё раз: браузер может использовать отдельное хранилище. После подготовки кеша доступны новая партия, все способы управления, пауза и история. Если браузер удалит данные сайта, для подготовки офлайн-доступа снова понадобится интернет.

В установленном окне вход называется «Приложение» и больше не предлагает повторную установку. Открытие раздела скрывает поле и останавливает таймер; закрытие сохраняет партию и прежнюю ручную паузу. **Прогресс сохраняется:** после полного закрытия приложения или перезагрузки можно продолжить последнюю партию, начать новую или открыть историю игр.

При запуске проверяется новая версия; при возвращении в приложение с сетью дополнительная проверка выполняется не чаще одного раза в час. Уведомление об обновлении появляется в меню и разделе «Приложение». Нажмите «Обновить», затем **«Обновить и перезапустить»**: игра дождётся сохранения текущей партии и предложит продолжить её после перезапуска. Если сохранение не удалось, обновление откладывается. «Позже» оставляет её без изменений. Само обнаружение обновления не перезагружает игру; другие открытые вкладки тоже не перезагружаются принудительно.

Service worker включён только в production-сборке, работает в пределах `/pyramids/` и использует отдельный кеш приложения. `npm run dev` работает без PWA-кеширования. Для установки и service worker нужен HTTPS (на GitHub Pages он уже есть) либо localhost при локальной проверке. Дополнительный сервер и изменения настроек Pages не требуются.

## Автосохранение и история игр

Игра сохраняет позицию, всю историю отмены и повтора последней партии, выбранное управление и накопленное время в IndexedDB. Ходы сохраняются по мере игры, время — дополнительно раз в секунду. Выделение диска, ошибки и незавершённые жесты не восстанавливаются. При возвращении время ждёт нажатия «Продолжить партию»; время вне приложения не учитывается.

«История игр» доступна в настройках, мобильном меню и настольной панели партии. Записи идут от новых к старым и содержат дату начала, режим, число стержней и дисков, ходы, время и статус. Список загружается по 50 записей. Продолжить можно только последнюю партию; старые записи сохраняют сводку без возможности возобновления. Победную последнюю партию можно открыть и отменить победный ход — запись снова станет «В процессе».

Новая запись появляется после «Играть» или «Начать заново». Незавершённая прежняя партия получает статус «Не завершена», победа остаётся победой. Закрытие настроек или отмена выбора управления не создаёт запись. Если два окна пытаются менять сохранение, устаревшее окно останавливается: закройте другое окно и выберите «Загрузить актуальное сохранение».

Сохранение работает офлайн в установленной PWA после подготовки кеша игры. Обновление service worker очищает только кеш ресурсов, а не IndexedDB. Перед обновлением приложение ждёт завершения записи. При проблемах с хранилищем можно продолжать играть, но появится «Прогресс не сохраняется»; повторить запись можно из уведомления, на телефоне — в меню. Повреждённое сохранение не загружается; доступные результаты остаются в истории.

Сохранения не шифруются, не являются защищёнными рекордами и не синхронизируются между устройствами. На iPhone Safari и приложение с главного экрана могут иметь отдельные данные. Приложение запрашивает persistent storage, если браузер поддерживает его; отказ не мешает игре. Ручная очистка данных сайта удаляет историю. При аварийном завершении ОС возможна потеря незавершённых записей: восстанавливается последнее успешно сохранённое состояние.

## На телефоне

Игровой экран помещается по ширине и высоте без прокрутки при обычном масштабе браузера, в том числе в горизонтальной ориентации. Сверху показаны режим, время и ходы; снизу — «Отменить», «Повторить», «Пауза» / «Продолжить» и «Меню». Поле занимает оставшееся место и учитывает системные отступы экрана.

При первом открытии без сохранения появляются настройки, затем выбор управления. Если сохранение есть, сначала предлагается продолжить последнюю партию. Закрытие настроек оставляет неподвижный предпросмотр с кнопкой «Настроить игру»; таймер ещё не запущен. Введённые параметры сохраняются при возврате из выбора управления и при повороте телефона.

В «Меню» находятся параметры партии, выбранное управление, позиция в истории, настройки, правила и перезапуск. Любое открытое окно скрывает поле и останавливает время. «Назад» возвращает в меню, закрытие — к партии; отмена выбора управления перед новой игрой возвращает к настройкам. Ручная пауза сохраняется. Перезапуск сразу начинает новую партию с прежними параметрами и управлением.

В низком экране можно прокручивать содержимое модалки: заголовок, закрытие и основные действия остаются видимыми, фон не прокручивается. Поворот и изменение размеров отменяют незавершённый жест, сохраняя партию. Компактная компоновка включается при ширине до 760 px либо при ширине до 1024 px и высоте до 500 px. Пользовательское масштабирование браузера не отключено.

Для трёх стержней минимальное число ходов с первого на последний — `2ⁿ − 1` в обычном режиме и `3ⁿ − 1` в хардкоре. При 10 дисках это 1023 и 59 048 ходов соответственно. История хранится целиком в обоих режимах.

## Проверка и сборка

```sh
npm run check:lockfile
npm run lint:architecture
npm test
npm run typecheck
npm run build
npm run preview
```

Проект использует публичный npm registry, закреплённый в `.npmrc`. Команда `npm run check:lockfile` проверяет адреса скачивания в lock-файле и запускается в GitHub Actions до `npm ci`. При добавлении зависимостей коммитьте обновлённый `package-lock.json`; адреса корпоративных зеркал в нём не допускаются.

Сборка находится в `dist/`. `npm run preview` запускает локальный просмотр сборки по адресу http://127.0.0.1:4173/pyramids/ (если порт занят, используйте порт из терминала). Сборка и preview используют базовый путь `/pyramids/`, а `npm run dev` по-прежнему открывает игру в корне `/`.

## Архитектура

Приложение организовано по Feature-Sliced Design. Слои зависят только от нижележащих; соседние срезы одного слоя не импортируют друг друга.

| Слой | Ответственность |
| --- | --- |
| `app` | Bootstrap React и PWA, глобальные стили и подключение страницы |
| `pages/game` | Компоновка экрана, черновик настроек, переходы общей модалки и соединение сценариев |
| `features/play-game` | Сессия, жесты, клавиатура, таймер, автопауза и последовательная очередь сохранения |
| `features/game-setup` | Формы настроек и выбора управления с демонстрацией |
| `features/game-history` | Чтение истории, пагинация и отображение результатов |
| `features/pwa` | Установка, офлайн-статус и обновление по подтверждению |
| `entities/game` | Чистые правила/reducer, типы, проверка сохранений, IndexedDB и отображение поля |
| `shared/ui`, `shared/lib` | Кнопка, диалог, иконки, hooks времени и определения компактного экрана |

`src/main.tsx` делегирует запуск в `app`. Внутри срезов код разделён на `model`, `ui` и `api` по необходимости. Отдельного слоя `widgets` нет: композиция единственного экрана принадлежит странице.

Контейнеры и hooks управляют состоянием и побочными эффектами. Компоненты отображения получают данные и callbacks через props: например, `InteractiveBoard` подключает жесты к `BoardView`, а история и PWA имеют отдельные hooks и views. Нативный диалог самостоятельно управляет фокусом; это локальная интерфейсная логика. Обновление PWA получает callback сохранения от страницы и не импортирует игровую сессию.

Импорты между срезами используют alias `@/` и явные экспорты `index.ts`; внутри среза — относительные пути. Shared предоставляет отдельные публичные API для каждого UI-компонента или библиотеки. `npm run lint:architecture` проверяет границы и публичные API через Steiger; команда включена в публикацию GitHub Actions. Правило о единственном потребителе среза отключено осознанно: независимые сценарии собираются на одной странице.

Стили компонентов находятся в CSS Modules рядом с UI. Страница не обращается к внутренним классам features/entities: варианты поля и правил передаются props, оформление внешнего элемента кнопки — `className`, параметры кнопок в подвале диалога — CSS-переменными. Глобальными остаются сброс, типографика, оформление документа и блокировка фоновой прокрутки. Браузерные тесты используют доступные названия, `data-testid` и семантические атрибуты поля; хеши CSS Modules не являются API.

Формат сохранений по-прежнему версии 1: имя базы, хранилища и ключи не изменены. Репозиторий пишет только изменённые снимки; очередь и обработка ошибок находятся в сценарии партии. Тест с зафиксированным сохранением старой production-сборки проверяет совместимость, включая будущие ходы и накопленное время.

## Браузерные проверки

Для браузерных тестов нужен установленный Google Chrome и движок WebKit:

```sh
npx playwright install webkit
npm run test:e2e
npm run test:pwa
```

Playwright сам запускает dev-сервер. Проверяются настройки, история, победа, клавиатура, модальные окна, мышь и касания. Мобильная компоновка проверяется в Chromium и WebKit: все сочетания стержней и дисков на экранах от 320×480 до 956×440, включая низкий горизонтальный экран 568×280, поворот, остановку времени, фокус и отсутствие обрезанных элементов. Настольные проверки сохранены. Снимки экранов сохраняются в `test-results/`. Проверки автосохранения включают настоящую IndexedDB в Chromium и WebKit, 59 048 ходов с полной отменой/повтором, запись только изменённых снимков, повреждённые данные, отказ хранилища, автопаузу и конфликт двух окон.

`npm run test:pwa` отдельно создаёт две production-сборки во временной папке и запускает сервер на порту 4175 с путём `/pyramids/`. В Chromium и WebKit проверяются manifest, размеры иконок, область service worker, подготовка кеша, повторный запуск без сети с восстановлением партии и истории, установка, модалки и обновление между сборками с подтверждением, сохранением партии и очисткой устаревших ресурсов. Результаты PWA-тестов находятся в `test-results-pwa/`. Также проверяются отказ регистрации, ограничение частоты проверок и отсутствие принудительной перезагрузки второй вкладки. Из-за [ошибки эмуляции офлайна в Playwright WebKit](https://github.com/microsoft/playwright/issues/42775) для этого движка тестовый сервер обрывает сетевые соединения; загрузка из service worker остаётся настоящей.

Для проверки обновления с конкретной старой версией сохраните её `dist/` в отдельной папке, затем запустите на новом коде:

```sh
PWA_BASELINE_DIR=/absolute/path/to/previous-dist npm run test:pwa
```

В этом режиме сервер использует настоящую старую сборку и новую. В обоих движках проверяются отложенное и подтверждённое обновление, сохранение позиции, времени, управления, полной отмены/повтора и холодный запуск без сети. Старую сборку и браузерные артефакты в Git добавлять не нужно.

PNG-иконки уже включены в репозиторий. После изменения `public/favicon.svg` их можно пересоздать командой `npm run icons` (нужен Google Chrome).

После публикации вручную проверьте системную установку на настоящих Android и iPhone: добавьте игру на главный экран, запустите через значок, дождитесь готовности офлайн-режима, полностью закройте, включите авиарежим и откройте снова. Убедитесь, что можно продолжить последнюю партию, поле помещается в обеих ориентациях и работают жесты. Также сверните игру и проверьте автопаузу, закройте через список приложений и восстановите позицию, время, отмену/повтор и историю. Автоматические тесты проверяют браузерную часть установки; системный диалог и добавление значка нужно проверять на телефоне.

## Первая публикация на GitHub Pages

Инструкция для публичного репозитория `vtkndrew/pyramids`, ветки `main` и стандартного домена GitHub Pages. Свой сервер, собственный домен и личный токен не нужны.

1. В терминале в папке проекта закоммитьте подготовленные изменения и отправьте их в GitHub:

   ```sh
   git add .github/workflows/deploy.yml vite.config.ts index.html src README.md package.json package-lock.json tsconfig.json steiger.config.js
   git commit -m "Configure GitHub Pages deployment"
   git push origin main
   ```

2. Откройте [репозиторий на GitHub](https://github.com/vtkndrew/pyramids). Сверху нажмите **Settings**, затем в меню слева — **Pages**. Можно сразу открыть [настройки Pages](https://github.com/vtkndrew/pyramids/settings/pages).
3. Найдите раздел **Build and deployment**. В выпадающем списке **Source** выберите **GitHub Actions**. Дополнительный workflow из шаблонов создавать не нужно: файл `.github/workflows/deploy.yml` уже есть в проекте. Ветку публикации и папку `/docs` выбирать тоже не нужно.
4. Перейдите во вкладку [Actions](https://github.com/vtkndrew/pyramids/actions) в верхнем меню репозитория. Слева выберите **Deploy to GitHub Pages**.
5. Справа над списком запусков нажмите **Run workflow**, оставьте ветку **main** и подтвердите кнопкой **Run workflow**. Это запустит публикацию после включения Pages, даже если первый автоматический запуск после push завершился ошибкой.
6. Откройте появившийся запуск. Дождитесь зелёной отметки у задания **deploy**: оно установит зависимости, запустит тесты, соберёт сайт и опубликует его. Развёрните шаг, если хотите посмотреть его вывод.
7. Откройте **https://vtkndrew.github.io/pyramids/**. Ссылка также появится в результатах публикации и в **Settings → Pages**. Теперь её можно отправлять другим людям: им не нужны аккаунт GitHub или установка приложения.

После первой настройки достаточно отправлять обновления в `main` командой `git push`: публикация запускается автоматически. Компьютер и локальный dev-сервер можно выключить после отправки изменений. Папки `dist` и `node_modules` добавлять в Git не нужно — сборка создаётся внутри GitHub Actions.

### Если что-то не получилось

- **Красная отметка во вкладке Actions:** откройте запуск → задание **deploy** → первый шаг с ошибкой. Если ошибка в **Configure GitHub Pages**, проверьте, что в **Settings → Pages → Source** выбрано **GitHub Actions**, затем снова выполните ручной запуск.
- **Workflow не появился:** во вкладке **Code** выберите `main` и проверьте наличие `.github/workflows/deploy.yml`. Файл должен быть закоммичен и отправлен в GitHub. Обновите страницу Actions.
- **Actions отключены:** в **Settings → Actions → General** разрешите GitHub Actions и использование официальных actions от GitHub. Затем повторите запуск.
- **404 после успешной публикации:** подождите несколько минут, проверьте адрес в **Settings → Pages** и открывайте именно `/pyramids/`, а не корень домена.
- **Игра показывает старую версию:** дождитесь успешного завершения последнего запуска, откройте раздел «Приложение» и примените доступное обновление. Если уведомления ещё нет, закройте и снова откройте игру с интернетом. Применение обновления сохраняет последнюю партию; «Начать заново» создаёт новую запись в истории.

Если переименовать репозиторий или подключить собственный домен, измените базовый путь, `id`, `start_url`, `scope` и правило офлайн-навигации в `vite.config.ts`.

Документация: [Vite — GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages), [выбор источника публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
