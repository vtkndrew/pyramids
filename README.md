# Пирамидки

Локальная головоломка на React, TypeScript и Vite. Перенесите пирамидку с первого стержня на последний: можно брать только верхний диск и класть его на пустой стержень либо на больший диск.

Адрес игры после публикации: **https://vtkndrew.github.io/pyramids/**.

## Запуск

Нужен Node.js 22.12+ (либо Node.js 20.19+) и npm.

```sh
npm install
npm run dev
```

Откройте адрес из терминала (обычно http://127.0.0.1:5173). Для остановки сервера нажмите Ctrl+C. После установки зависимостей игра работает локально без доступа к интернету, внешних шрифтов и сервисов.

## Управление

- Перед началом выберите 3–6 стержней и 3–10 дисков. По умолчанию: 3 стержня и 5 дисков.
- Выберите режим: «Обычный» (по умолчанию) разрешает переносы на любой подходящий стержень; «Хардкор» — только на соседний слева или справа. Первый и последний стержни не являются соседями. Правило размеров дисков действует в обоих режимах. Режим применяется только при начале новой игры и сохраняется при перезапуске.
- После «Начать игру» открывается окно выбора управления с демонстрацией. В обычном режиме по умолчанию выбрано «Перетаскивание», в хардкоре — «Свайпы». Партия и таймер запускаются только после «Играть». Закрытие окна возвращает к настройкам без сброса существующей партии.
- Нажмите на исходный стержень, затем на стержень назначения. Повторный клик по исходному снимает выбор. Допустимые назначения подсвечиваются.
- «Перетаскивание»: потяните из любой части ячейки непустого стержня и отпустите над нужной ячейкой. Переносится только верхний диск. Отпускание вне поля или над исходным стержнем отменяет перенос.
- «Свайпы» доступны только в хардкоре: смахните по ячейке влево или вправо — верхний диск переместится на один соседний стержень. Длина свайпа не увеличивает расстояние. Нажатия продолжают работать и при включённых жестах.
- Клавиатура: цифра 1–6 выбирает исходный стержень, следующая — целевой. Escape снимает выбор или отменяет жест. Tab / Shift+Tab перемещают фокус, Enter или пробел активируют кнопки; стрелки меняют настройки. Игровые клавиши не действуют в формах, модалках и на паузе.
- Кнопка «Управление» (на телефоне — в «Меню») открывает выбор способа во время партии. Поле скрывается и время останавливается; «Применить» меняет управление без сброса позиции, истории и времени. Закрытие без применения сохраняет прежний способ. Ручная пауза остаётся включённой, если была включена до открытия окна.
- «Отменить» и «Повторить» позволяют пройти всю историю. Новый допустимый ход после отмены удаляет будущую ветку. Ошибка или выбор диска историю не меняют.
- «Начать заново» сразу сбрасывает текущую партию, сохраняя настройки и способ управления, без повторного окна выбора.
- «Настройки» (на телефоне — в «Меню») открывает форму. «Начать игру» открывает выбор управления, а «Играть» применяет выбранные значения и создаёт новую партию. «Назад к игре» сохраняет текущую партию и историю.
- После победы можно отменить ход и продолжить игру или повторить ход для возврата к победе.
- «Пауза» останавливает таймер и полностью скрывает поле. На паузе нельзя делать, отменять и повторять ходы, но доступны настройки и перезапуск. «Продолжить» возвращает ту же позицию и продолжает отсчёт; выделение диска сбрасывается. Возврат из настроек сохраняет ручную паузу. Новая игра или перезапуск снимают паузу и сбрасывают время. После победы кнопка паузы недоступна.
- Таймер запускается с началом партии. В настройках и после победы время стоит на паузе; при возврате к игре или отмене победного хода отсчёт продолжается. Отмена и повтор не отматывают время. Новая игра и «Начать заново» сбрасывают таймер. В фоновой вкладке время продолжает идти.

Партия и способ управления хранятся в памяти: обновление страницы сбрасывает их. Все стержни и диски адаптируются к ширине поля без горизонтальной прокрутки. В режимах жестов на поле отключено выделение текста; в настольной компоновке с перетаскиванием прокручивать страницу можно за пределами поля. PWA пока не добавлена.

## На телефоне

Игровой экран помещается по ширине и высоте без прокрутки при обычном масштабе браузера, в том числе в горизонтальной ориентации. Сверху показаны режим, время и ходы; снизу — «Отменить», «Повторить», «Пауза» / «Продолжить» и «Меню». Поле занимает оставшееся место и учитывает системные отступы экрана.

При первом открытии сразу появляются настройки, затем выбор управления. Закрытие настроек оставляет неподвижный предпросмотр с кнопкой «Настроить игру»; таймер ещё не запущен. Введённые параметры сохраняются при возврате из выбора управления и при повороте телефона.

В «Меню» находятся параметры партии, выбранное управление, позиция в истории, настройки, правила и перезапуск. Любое открытое окно скрывает поле и останавливает время. «Назад» возвращает в меню, закрытие — к партии; отмена выбора управления перед новой игрой возвращает к настройкам. Ручная пауза сохраняется. Перезапуск сразу начинает новую партию с прежними параметрами и управлением.

В низком экране можно прокручивать содержимое модалки: заголовок, закрытие и основные действия остаются видимыми, фон не прокручивается. Поворот и изменение размеров отменяют незавершённый жест, сохраняя партию. Компактная компоновка включается при ширине до 760 px либо при ширине до 1024 px и высоте до 500 px. Пользовательское масштабирование браузера не отключено.

Для трёх стержней минимальное число ходов с первого на последний — `2ⁿ − 1` в обычном режиме и `3ⁿ − 1` в хардкоре. При 10 дисках это 1023 и 59 048 ходов соответственно. История хранится целиком в обоих режимах.

## Проверка и сборка

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

Сборка находится в `dist/`. `npm run preview` запускает локальный просмотр сборки по адресу http://127.0.0.1:4173/pyramids/ (если порт занят, используйте порт из терминала). Сборка и preview используют базовый путь `/pyramids/`, а `npm run dev` по-прежнему открывает игру в корне `/`.

Чистая игровая логика и история находятся в `src/game.ts`, тесты — в `src/game.test.ts`. Интерфейс — в `src/App.tsx` и `src/styles.css`.

Для браузерных тестов нужен установленный Google Chrome и движок WebKit:

```sh
npx playwright install webkit
npm run test:e2e
```

Playwright сам запускает dev-сервер. Проверяются настройки, история, победа, клавиатура, модальные окна, мышь и касания. Мобильная компоновка проверяется в Chromium и WebKit: все сочетания стержней и дисков на экранах от 320×480 до 956×440, включая низкий горизонтальный экран 568×280, поворот, остановку времени, фокус и отсутствие обрезанных элементов. Настольные проверки сохранены. Снимки экранов сохраняются в `test-results/`.

## Первая публикация на GitHub Pages

Инструкция для публичного репозитория `vtkndrew/pyramids`, ветки `main` и стандартного домена GitHub Pages. Свой сервер, собственный домен и личный токен не нужны.

1. В терминале в папке проекта закоммитьте подготовленные изменения и отправьте их в GitHub:

   ```sh
   git add .github/workflows/deploy.yml vite.config.ts index.html src/App.tsx README.md
   git commit -m "Configure GitHub Pages deployment"
   git push origin main
   ```

2. Откройте [репозиторий на GitHub](https://github.com/vtkndrew/pyramids). Сверху нажмите **Settings**, затем в меню слева — **Pages**. Можно сразу открыть [настройки Pages](https://github.com/vtkndrew/pyramids/settings/pages).
3. Найдите раздел **Build and deployment**. В выпадающем списке **Source** выберите **GitHub Actions**. Дополнительный workflow из шаблонов создавать не нужно: файл `.github/workflows/deploy.yml` уже есть в проекте. Ветку публикации и папку `/docs` выбирать тоже не нужно.
4. Перейдите во вкладку [Actions](https://github.com/vtkndrew/pyramids/actions) в верхнем меню репозитория. Слева выберите **Deploy to GitHub Pages**.
5. Справа над списком запусков нажмите **Run workflow**, оставьте ветку **main** и подтвердите кнопкой **Run workflow**. Это запустит публикацию после включения Pages, даже если первый автоматический запуск после push завершился ошибкой.
6. Откройте появившийся запуск. Дождитесь зелёной отметки у задания **deploy**: оно установит зависимости, запустит тесты, соберёт сайт и опубликует его. Развёрните шаг, если хотите посмотреть его вывод.
7. Откройте **https://vtkndrew.github.io/pyramids/**. Ссылка также появится в результатах публикации и в **Settings → Pages**. Теперь её можно отправлять другим людям: им не нужны аккаунт GitHub или установка приложения.

После первой настройки достаточно отправлять обновления в `main` командой `git push`: публикация запускается автоматически. Компьютер и локальный dev-сервер можно выключить после отправки изменений. Папки `dist` и `node_modules` добавлять в Git не нужно — сборка создаётся внутри GitHub Actions.

### Если что-то не получилось

- **Красная отметка во вкладке Actions:** откройте запуск → задание **deploy** → первый шаг с ошибкой. Если ошибка в **Configure GitHub Pages**, проверьте, что в **Settings → Pages → Source** выбрано **GitHub Actions**, затем снова выполните ручной запуск.
- **Workflow не появился:** во вкладке **Code** выберите `main` и проверьте наличие `.github/workflows/deploy.yml`. Файл должен быть закоммичен и отправлен в GitHub. Обновите страницу Actions.
- **Actions отключены:** в **Settings → Actions → General** разрешите GitHub Actions и использование официальных actions от GitHub. Затем повторите запуск.
- **404 после успешной публикации:** подождите несколько минут, проверьте адрес в **Settings → Pages** и открывайте именно `/pyramids/`, а не корень домена.
- **Игра показывает старую версию:** дождитесь успешного завершения последнего запуска и обновите страницу с очисткой кеша браузера.

Если переименовать репозиторий или подключить собственный домен, базовый путь в `vite.config.ts` нужно будет изменить.

Документация: [Vite — GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages), [выбор источника публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
